## Shared live and historical interpretation

`protocol/t4/semantics.py` defines event meaning for live DEP and T4_LOGS records. State changes, source causes, basic/advanced diagnostics, commands, manual/channel codes and event classes use the same source-backed interpretation. Unknown and receiver payloads are not dumped as opaque raw bytes. State, movement and display logic retain their established adapters.

A frame with multiple T4 payloads retains separate bounded `t4_evidence` parts and payload order. The compatibility live-state view is still merged for existing entities, while incident interpretation uses the individual parts so one event's cause is not attached to another. At most 16 parts are retained per frame, with an explicit truncation flag.

A consecutive retransmission with the same protocol identity, timestamp and content is suppressed for two seconds. Anonymous observations are not assumed to be duplicates. A retained true Obstruct flag is not a new edge; an unseeded true flag establishes a baseline. A confirmed false-to-true edge or an explicit controller force-limiter intervention may produce an obstruction event. Reconnect starts a new observation baseline.

## Incident timeline

Diagnostics include a 256-record in-memory timeline of accepted/failed HA commands, readback verification, live/module/controller events, measurements, motor load, interface logs and inferred state reversals. Each entry identifies source, local sequence, session, HA receipt time and observation age. Fresh measurement fields retain their individual ages. Animation ticks and cached position fields are not new measurements.

The timeline is bounded evidence, not a permanent archive or a safety controller. Controller/interface history is retrieved with the existing read-only refresh buttons. History imports remain history and never replay into live gate state. Repeated imports deduplicate within a session; distinct connection epochs are retained separately. Existing motion traces retain five traces of 300 samples, with rollover, and remain available when debug recording is enabled.

Unzoned controller/module timestamps are retained as reported, not silently corrected or sorted together as trusted UTC instants. HA receipt sequence orders observations. Batch position/load reads are sequential, not an atomic physical sample.

`0x88` establishes command arrival, not an external actor. A nearby HA command is labelled `temporal_only`, not proven causation. A static limiter level is a load observation, not an intervention. Explicit controller diagnostic codes are labelled reported; reversal/abnormal-stop heuristics are inferred. Physical cause and actor remain unknown unless independent evidence establishes them.

NHK DIAGNOSTIC causeCodeX91 also records a controller_diagnostic abnormal-stop entry with the raw cause/basic/advanced codes and evidence_source=nhk_diagnostic, independently of the legacy five-second motion heuristic. Diagnostic DoorStatus does not start or clear that heuristic's movement tracking. Duplicate suppression and scan rate limits still apply. This preserves the reported #75 sequence after a 21-second opening without requiring a matching T4 frame. It does not establish a universal NHK-to-T4 mapping or a physical cause. Later generic stops remain unclassified; a zero counter is not proof that no premature stop occurred.

## Hardware, inverter and power

BlueBus and I/O use the reviewed decoders and installed-item masks. Hardware D2 and inverter D4 use the same app hardware decoder with controller-supplied availability and scales. Motor 1 and motor 2 fields remain distinct. Primary service-voltage and temperature values are included where descriptors make them available. Missing installation metadata is explicit; no aggregate motor percentage is invented.

Optional diagnostic cards are disabled by default. Enabling I/O/hardware monitoring adds only the reviewed D1/D2 GETs to moving polls. Inverter moving reads require complete verified D4 INFO descriptors first. User commands and Stop keep priority. Failed reads do not refresh the capture age of retained evidence, and late results after reconnect/shutdown are discarded.

NHK battery, reset, current and maintenance events retain their reported codes and device class, without MACs or an invented battery percentage. Dedicated PSU transport/layout, automation-state structures, other/visual layouts and test-history records remain gap-backed blocked readers. Maintenance reset remains blocked before any I/O because its permissions, payload and recovery procedure are not established.

## Counter and maneuver-history uncertainty

DMP maintenance threshold, maintenance count and total counter are distinct controller registers. Diagnostic counter cards apply verified INFO scaling when available and retain the raw values alongside. NHK ManoeuvreCount/ManoeuvreThLimit are a separate channel; their relation and reset epochs are not inferred, and an NHK event no longer overwrites both DMP counters.

04/DA is eight reported AutomationStatusDiagnostics slots. Slot order follows the vendor array, but newest-slot identity, initialization and freshness are not established universally. All-zero history retains vendor `ok` labels with `all_zero_unverified`; it does not become eight confirmed successes. The existing failure-count sensor is unknown for this ambiguous all-zero case, with explanatory attributes. An unchanged buffer cannot establish that every recent maneuver succeeded.

04/DB is decoded only through verified controller INFO scalar/indexed formats. It is not assumed to be AdvancedDiagnostic bytes or to align with 04/DA slots. Structured/signed or missing formats are explicitly unavailable or blocked. Model profiles explain MC824H/HYKE and ROBUS FG01h evidence limitations without granting capabilities or guessing motor identities.

## Export and retention

Integration diagnostics include the screen report, profile, incident timeline, observations and gap/capability explanations. No extra export service or credentials are required. Standard HA diagnostics can be downloaded even if setup has failed. Output uses field allowlists, bounded histories/values, unknown-payload suppression, standard key redaction and recursive configured-secret redaction. Radio codes, pairing/password registers, client names and unreviewed receiver payloads are not added to the timeline.

Source basis: MyNice Pro 2.18 T4LogReply, T4InputOutputDiagnostic, T4HardwareDiagnostic, T4AutomationLast8ManeuversStatus, INFO-driven advanced-history rendering, existing sanitized fixtures and the supplied DA/DB/D4 research. An arm64 native library and matching Pro split-APK library bytes were supplied on 2026-11-25. Version association and native decoder contracts still need audit, so unverified native structures remain explicit gaps.

## Normal-use beta checks

Install the phase beta and restart HA. No controller relearning, force/safety parameter change, counter reset or deliberate obstruction is needed. Compare ordinary open/Stop/close/reversal evidence and app logs. Optionally enable a diagnostic card, compare values and ages, then download sanitized diagnostics. An all-zero maneuver history may now correctly show unknown instead of zero failures. Check that module clock offsets remain explicit and that all existing entities retain their IDs.
